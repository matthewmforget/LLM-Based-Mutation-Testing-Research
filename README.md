# LLM-Based Mutation Testing Research Project

## Overview
This project explores the intersection of mutation testing and large language models (LLMs), focusing on the use of GPT-3.5-turbo to generate code mutations and comparing their effectiveness against traditional mutation testing methods using PIT (PITest).

## Key Components
- **Mutation Testing**: An introduction to mutation testing, explaining how it works and its significance in software testing.
- **PIT (PITest)**: Utilizes the PITest framework to generate mutants from a set of Java projects, assessing the quality and effectiveness of these mutants.
- **LLM Integration**: Leveraging the capabilities of GPT-3.5-turbo to generate mutant code based on provided examples, allowing for a comparison of semantic correctness and functionality.
- **Experimentation**: Detailed experimentation involving:
  - Selection of mutation operators.
  - Comparison of mutants generated by PIT and GPT-3.5-turbo.
  - Evaluation metrics such as runnable mutants and mutation scores.
  
## Results
The project presents findings on the similarities and differences between the mutants generated by both methods, providing insights into the potential of using LLMs for mutation testing.

## Methodology

### Project Selection
I selected **10 Apache Maven projects** for this research, focusing on a diverse range of libraries to ensure a comprehensive evaluation of mutation testing techniques. The projects were chosen based on their popularity, complexity, and available test coverage, which are essential factors for effective mutation testing.

### Mutation Testing with PIT
1. **Setup**: For each selected Maven project, I configured PIT (PITest) to run mutation tests. This involved integrating the PIT plugin into the Maven build process, ensuring that it could generate mutants effectively.
  
2. **Mutant Generation**: I executed PIT to create a set of mutants for each project. This process involved altering specific lines of code to simulate potential faults, thereby allowing the evaluation of the existing test suite's effectiveness.

3. **Analysis**: After running the mutation tests, I collected mutation scores, which indicated the percentage of mutants that were killed (i.e., detected by the tests) compared to the total number of mutants generated. Additionally, I noted the compilability rate of the mutants, determining how many of them could successfully compile without errors.

### LLM-Based Mutation
1. **Mutation Generation Using LLM**: Following the initial mutation testing with PIT, I used GPT-3.5-turbo to generate additional code mutations for the same projects. I provided the LLM with examples of the mutations created by PIT, enabling it to learn and replicate the mutation patterns.

2. **Evaluation**: For the mutants generated by the LLM, I conducted a similar analysis:
   - **Mutation Scores**: I calculated the mutation scores for the LLM-generated mutants to compare their effectiveness against those produced by PIT.
   - **Compilability Rate**: I also assessed the compilability of the LLM-generated mutants, determining how many could compile successfully.

### Comparison of Results
Finally, I compared the mutation scores and compilability rates of both the PIT-generated and LLM-generated mutants. This analysis provided valuable insights into the effectiveness and reliability of using LLMs in mutation testing, contributing to the broader understanding of their potential in software quality assurance.
